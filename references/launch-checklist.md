# 上线验收清单

## 上线前

- [ ] 欢迎语、关键词回复、菜单文案已全部备份并迁入 `replies.zh-CN.json`
- [ ] 数据库迁移已执行（只新增表，不删数据）
- [ ] 环境变量全部是服务端变量，没有 `NEXT_PUBLIC_` / `VITE_` 前缀
- [ ] EncodingAESKey 来自微信公众号开发者后台（新配置点击「随机生成」，已有配置沿用当前值），与服务端 `WECHAT_MP_AES_KEY` 完全一致，未由 AI 或本地脚本生成
- [ ] 功能开关：`WECHAT_MP_WEBHOOK_ENABLED=true`、`WECHAT_MP_LOGIN_ENABLED=false`，先只开回调
- [ ] `curl` 回调地址，确认没有 Cloudflare 挑战页、没有 302 到登录页、没有缓存头
- [ ] 微信后台提交 URL 校验通过

## 真机（至少一台 iPhone + 一台 Android + 一台电脑）

- [ ] 新用户：扫码关注 → 收到欢迎语
- [ ] 老粉丝：直接发登录关键词 → 收到验证码
- [ ] 桌面：发配对码 → 桌面页面 2–6 秒内自动登录
- [ ] 手机浏览器：「复制登录码并打开微信」→ 粘贴发送 → 回到浏览器自动登录
- [ ] 微信内：发关键词 → 点一键登录链接 → 回到原来那一页
- [ ] 错误码、过期码、已用过的码，各自提示正确
- [ ] 每一条旧关键词回复都还能触发
- [ ] 已登录状态打开一键登录链接：要求确认，不会悄悄绑定
- [ ] 老账号绑定微信后，用微信登录进入的是老账号
- [ ] 一个微信已绑定 A 账号，再绑 B 账号：被拒绝
- [ ] 回调耗时（含冷启动）< 5 秒

## 页面与转化流程

- [ ] 登录页说明实际可获得的收益；下载和同步面板的标题、按钮对应用户刚才的操作
- [ ] 桌面、手机浏览器、微信内分别检查操作顺序、复制反馈、等待/成功/过期/错误状态
- [ ] 登录后回到原站内位置，能继续下载刚才选择的格式，同步时本机记录正确合并
- [ ] 关闭提醒后不会自动重开，同类主动提醒共用冷却时间，已有登录引导的页面不重复提示
- [ ] 手机与桌面、浅色与深色下，二维码、登录码、主按钮和说明均清晰可用
- [ ] 收益、步骤、按钮、alt/aria、错误提示沿用项目现有语言资源与 locale API
- [ ] 按入口区分曝光、打开引导、开始登录、登录成功及下载点击/同步成功，事件含义与实际触发点一致

页面结构与截图参考 [登录与转化设计](login-design.md)，事件口径参考 [埋点与转化率](analytics.md)。

## 上线后 72 小时

- [ ] 打开 `WECHAT_MP_LOGIN_ENABLED=true` 并重新部署
- [ ] 每天看：数据库新增微信身份数、`wechat_code_error` 占比、限流日志
- [ ] 公众号后台：新增关注、取消关注
- [ ] 如果 `wechat_code_error` 偏高，检查手动输码的提示文案和码有效期
